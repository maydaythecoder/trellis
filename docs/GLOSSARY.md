# Glossary

Terms used across the code and the documents, alphabetical. Each entry says
where the thing lives and which ADR holds it. "Lives in" names the defining
file; follow the ADR for the reasoning. The structure of a run is in
`docs/ARCHITECTURE.md`.

| Term | Definition | Lives in | ADR |
|---|---|---|---|
| **adapter tier** | See *tier*. | | |
| **ask_human** | A tool offered only to a queued task's run: a question with at most eight options. Allowed through the gates, it ends the run unconverged; the answer is input to the next run, never a verdict on this one. | `ToolCall::AskHuman` in `crates/trellis-loop/src/agent.rs`; `ASK_HUMAN` in `registry.rs` | 0026 §1, 0004 |
| **audit branch** | The integration branch. Green ticket and feature branches merge into `audit` with `git merge --no-ff`; conflicts are resolved and gates and the security audit run there; then `audit` is promoted into `dev` by pull request. Not to be confused with a *governance audit*. | `docs/BUILD_SYSTEM.md` "Branches" | 0051 |
| **audit mode** | `AuditMode::Verified` or `AuditMode::Reviewed`, one per caller of a changed symbol. See *Verified vs Reviewed*. | `crates/trellis-checks/src/verdict.rs` | 0003 |
| **blast radius** | The call sites that reach a symbol, found by walking incoming edges breadth-first. Reported as `RadiusReport`: `certain` (through `Resolved` edges), `ambiguous` (through `Candidates`), and its `RadiusCoverage`. Exposed to the model as the `blast_radius` tool and to people as `trellis radius`. | `blast_radius` in `crates/trellis-index/src/radius.rs` | 0002, 0014 |
| **budget** | Per-run ceilings on iterations, wall clock and tokens, from `.trellis/config.toml`, accounted through `tracing`. On exhaustion the loop grants one more turn, then stops unconverged. Budgets divide across partitions; they never multiply (rule 9). | `Budget` in `crates/trellis-loop/src/budget.rs` | 0008, 0026 §5 |
| **candidate edge** | An edge whose target is `Target::Candidates`: a known finite set of first-party definitions, all recorded, none chosen. Counted as `reached_ambiguous` in a radius, and unpartitionable (rule 6). | `Target` in `crates/trellis-index/src/graph.rs` | 0002 |
| **carry-back** | Bringing what a writer changed in its throwaway clone back into the repository, through trellis's own write path and under the same refusals as any write. | `crates/trellis-loop/src/isolate.rs`, `agent_clone.rs` | 0032 |
| **claim** | A worker taking a queued task: a hard link of the task file into `claimed/`, which fails if the name exists, so exactly one claimer wins. A `Claim` is consumed by `finish` or `release`. A claim left by a dead worker is a *stale claim* and is listed, not re-run. | `Queue::claim`, `Claim` in `crates/trellis-queue/src/lib.rs`; `stale.rs` | 0020 |
| **clean worktree** | The precondition for a run: no uncommitted changes, so rollback can be `git reset --hard` to a recorded commit (rule 7). | `trellis_vcs::snapshot` in `crates/trellis-vcs/src/lib.rs` | 0009 |
| **compaction** | Fitting a request to `[model] context_bytes` by replacing the observation text of the oldest turns with one `elided: <tool> <target>, N bytes` line. Elision, not summary: calls, verdicts and turn order are untouched, so convergence cannot change. Each compaction is recorded in the trail. | `Compacted`, `RequestedCompaction` in `crates/trellis-loop/src/adapter.rs` | 0024 §5, 0033 |
| **control dial** | `[control] mode`: `auto` (no human gate) or `approve` (listed tool calls wait for a person). Set by `--approve` / `--auto`. Implemented as an `ApprovalGate`. | `ControlMode` in `crates/trellis-cli/src/config.rs`; `ApprovalGate` in `crates/trellis-loop/src/gate.rs` | 0018 |
| **converged** | `Outcome::Converged`: the model said `done`, the last check produced a passing `Verdict`, nothing changed the tree after it, and the governance audit passed. The only outcome that leaves edits in place. | `run_seeded` in `crates/trellis-loop/src/agent.rs` | 0004, 0005 |
| **custom tool** | A repository's own command, declared in `[[tools.custom]]` with a name, description, argv and JSON Schema. Loaded only when trusted, runs in a throwaway clone, and returns `ToolResult::Output`, never a verdict. | `CustomTool` in `crates/trellis-loop/src/registry.rs` | 0023 §6, 0032 |
| **doubt** | The unbound count reported beside reach: call sites in the touched files that bound to nothing. An over-approximation, deliberately. `doubt_in_files` gives it for the files a run changed. | `RadiusCoverage::unbound_in_touched_files`; `FileDoubt` in `crates/trellis-index/src/radius.rs` | 0014 |
| **focus note** | The one vault note a run is given as context (`--focus <stem>`): compiled with its parent chain, root first, into a context block. | `compile` in `crates/trellis-vault/src/compile.rs` | 0017 |
| **G0–G7** | The gates in `scripts/gates/`, run in order by `run-all.sh`: G0 `ticket-ready.sh` (issue is workable), G1 `build.sh`, G2 `test.sh`, G2b `guards.sh` (guard suite; needs a runtime on 127.0.0.1:11434), G3 `lint.sh`, G4 `no-stubs.sh`, G5 `security.sh`, G6 `ticket-verify.sh` (the ticket's own Verify command), G7 (exit 3 for `risk:high` or `surface:public`: a person approves). The full table is in `docs/BUILD_SYSTEM.md` "Gates". | `scripts/gates/` | 0051 (branch base), 0004 (a pass comes from a command that ran) |
| **gate (tool gate)** | Something the orchestrator consults before dispatching a tool call. Ordered; the first `Deny` wins. A gate can allow or deny, never rewrite and never pass. Built-in gates: `GovernanceGate` (always first), `BashPolicyGate`, `HookGate` (`pre_tool`), `ApprovalGate`. Not the same as the G-numbered build gates. | `ToolGate`, `GateDecision` in `crates/trellis-loop/src/gate.rs`; `run_gates_and_tool` in `orchestrator.rs` | 0018 |
| **governance** | Rules in `.trellis/governance/*.toml`, each `non-negotiable` or `nice-to-have`, each a `forbid` (substring that must not appear) or `deny-write` (paths no run may edit). Matching is substring only. | `Rule`, `Rank`, `Mechanism` in `crates/trellis-checks/src/governance.rs` | 0004 |
| **governance audit** | The `forbid` rules evaluated over the files the run touched, producing a `Verdict` of kind `Governance`. Run on every `done`, whether or not the model asked, through the ungated door. A non-negotiable violation stops convergence. | `governance_audit` in `crates/trellis-checks/src/lib.rs`; `Handle::audit_governance` | 0004, 0018 |
| **heartbeat** | `trellis work`: the loop that claims queued tasks, runs them, and evaluates routines on each tick. Generic over a `Runner`, so its decisions are tested without a model. | `work`, `Runner` in `crates/trellis-queue/src/lib.rs`; `crates/trellis-cli/src/work.rs` | 0020, 0026 |
| **hook** | A repository argv run at a fixed point, JSON on stdin: `input`, `before_run`, `pre_tool`, `post_tool`, `turn_end`, `after_run`. `pre_tool` can refuse a call and `input` a task; none can pass a check. Loaded only when trusted; runs in a throwaway clone. | `HookConfig`, `Hooks` in `crates/trellis-loop/src/hooks.rs` | 0023 §5, 0032 |
| **index** | The call graph of first-party code: tree-sitter parse, then resolution into edges, cached in `.trellis/index.bin`. Has no dependency on a model. `trellis index` builds it and prints the bound share, which is a lower bound on recall, not recall. | `crates/trellis-index/`; `build_cached` in `resolve.rs` | 0001, 0015 |
| **integrated check** | After a multi-agent plan's partitions merge, `typecheck` and `run_tests` over the whole root. Only these verdicts can converge the run; partition-local passes never do (rule 6). | `Supervisor::run_integrated` in `crates/trellis-loop/src/integrate.rs` | 0042 |
| **ModeCounts** | `{ verified, reviewed }` in a trail's factual section. No `total()`, on purpose (rule 4). Filled from `coverage.json` when the test run produced one; zero and labelled "not measured" otherwise. | `crates/trellis-trail/src/lib.rs`; `audit_modes` in `crates/trellis-cli/src/run_cmd.rs` | 0003 |
| **orchestrator (code)** | The single-owner actor inside `trellis-loop` that holds the index and the only write path. The loop talks to it through a `Handle`; every tool call passes its gates. If it dies the run stops with `NotConverged::OrchestratorGone`. | `Orchestrator`, `Handle` in `crates/trellis-loop/src/orchestrator.rs` | 0005, 0018 |
| **orchestrator (build agent)** | `claude --agent orchestrator`: the Claude Code session that picks tickets, dispatches subagents, runs the gates and merges into `audit`. It cannot write files or push `main`. Unrelated to the code orchestrator. | `.claude/agents/orchestrator.md`; `docs/BUILD_SYSTEM.md` | 0051 |
| **partition** | A set of work units an agent may work on concurrently with others, because their radii are disjoint. Units reached through unresolved or candidate edges go together into one *conservative* partition. Plans are staged: shared work first, then the parallel stage, each partition in its own git worktree. | `Partition`, `WorkUnit`, `plan` in `crates/trellis-loop/src/partition.rs`; `Supervisor` in `supervise.rs` | 0016, 0037, 0045 |
| **pass_env** | The provider-key variables a process agent's profile names to get back; every other child process has them removed. | `ProfileFile::pass_env` in `crates/trellis-queue/src/profile.rs` | 0024 §3, 0026 §11 |
| **process agent** | A profile with `command = [argv]` instead of `model`. Its command runs in a throwaway clone; what it changed is carried back; then the same checks `trellis check` runs, plus governance, decide. Requires trust. | `crates/trellis-cli/src/process_agent.rs`; `crates/trellis-loop/src/agent_clone.rs` | 0026 §11, 0032 |
| **ProcessOutput** | The raw result of a process that ran: command, exit code, output, duration. Public to read; constructing one buys nothing, because the `Verdict` constructors that consume it are `pub(crate)`. | `crates/trellis-checks/src/lib.rs` | 0004 |
| **profile** | An agent definition at `.trellis/agents/<name>.toml`: role, instructions, model or command, tools, `allow_write`, control mode, skills, budget, services. Run-time state (pause, budget raise) is an overlay in the git dir. Examples in `examples/agents/`. | `ProfileFile`, `Profile` in `crates/trellis-queue/src/profile.rs` | 0026 §4 |
| **pyright backstop** | An opt-in second pass (`[index] backstop = "pyright"`) that asks `pyright-langserver` about call sites the resolver left `Unresolved` or `Candidates`. Never queried for `Resolved` sites. Its edges are tagged `EdgeSource::Pyright`. Its recall is pending a human audit. | `crates/trellis-index/src/pyright_backstop.rs` | 0031 |
| **radius** | See *blast radius*. | | |
| **RadiusCoverage** | The coverage attached to every blast radius: `reached_resolved`, `reached_ambiguous`, `unbound_in_touched_files`, `touched_files`, and the unbound count by reason and by file. Two facts, never a ratio: no `total()`, no fraction, because reach and doubt are counted over different populations (rule 3). | `crates/trellis-index/src/radius.rs` | 0014, 0002 |
| **recall / bound** | Recall is measured only by a hand audit (72.0% at the time of writing, method and interval in `docs/01-v0.1-measure.md` and ADR 0012). The figure `trellis index` prints is what the resolver bound, a lower bound on recall. The rules for these numbers load from `.claude/rules/index-soundness.md`. | `docs/BENCHMARK_AND_EVAL.md` | 0011, 0012, 0015 |
| **RecordedCheck** | A check as read back from a trail. Inert: `passed` means "the trail says it passed". Nothing accepts it where a `Verdict` is required. | `crates/trellis-trail/src/untrusted.rs` | 0007 |
| **resolved edge** | An edge whose target is `Target::Resolved`: exactly one first-party definition matches and nothing nearer shadows it. The only kind that may be used for partitioning. | `Target` in `crates/trellis-index/src/graph.rs` | 0002 |
| **rollback** | On any outcome other than convergence: reset to the snapshot's commit, remove untracked files the run created, re-read and verify by content every path the run wrote. Complete for trellis's own writes; best-effort against a command that writes by absolute path. A failed rollback is reported loudly and the trail is still written. | `Snapshot::rollback_written`, `written_differ` in `crates/trellis-vcs/src/lib.rs`; `rollback_run` in `crates/trellis-cli/src/run_cmd.rs` | 0009, 0032, 0046 |
| **routine** | A schedule and a task template at `.trellis/routines/<name>.toml`. `work` evaluates routines each tick; a due fire passes its concurrency policy (`coalesce`, `skip`, `always`) and becomes a pending task. Five-field cron, parsed by hand. | `RoutineFile`, `Routine` in `crates/trellis-queue/src/routine.rs`; `cron.rs` | 0026 §7 |
| **rpc** | `trellis rpc`: JSONL commands on stdin, events on stdout. A `prompt` runs through `cmd_run_with`. The interface the desktop and the planned Go TUI use. | `crates/trellis-cli/src/rpc.rs` | 0025 §5, 0052 |
| **S1–S21** | Soft spots: numbered risks referenced across the documents, each with a severity and a patch. | `docs/RISK_REGISTER.md` | — |
| **scripted model** | A `Model` that plays a fixed JSON script (`--model scripted:<path>`). Real loop, real files, real checks, real rollback, with judgement stubbed. Never a model floor (S7). | `ScriptedModel` in `crates/trellis-loop/src/scripted.rs` | 0005 |
| **Seal** | A private unit struct inside `verdict.rs`, held by every `Verdict`. Because nothing outside that module can name it, `Verdict` cannot be built by struct literal anywhere else. | `crates/trellis-checks/src/verdict.rs` | 0004 |
| **skill** | A procedure at `.trellis/skills/<name>/SKILL.md` in the Agent Skills format. Names and descriptions go into the prompt; the body enters only when the model calls `read_skill`. A skill informs and does not bind. | `crates/trellis-loop/src/skills.rs` | 0019, 0039 |
| **snapshot** | The recorded `HEAD` a run can return to, taken after every pre-run refusal and before the first write. | `Snapshot`, `snapshot` in `crates/trellis-vcs/src/lib.rs` | 0009 |
| **steering** | Text a person sends into a running run (`steer`, `follow_up`), delivered immediately before the next model request and recorded in the trail verbatim up to 2,000 characters. | `Steering`, `SteeringLog` in `crates/trellis-loop/src/agent.rs` | 0034 |
| **throwaway clone** | A `git clone --no-hardlinks` under the system temp directory in which `bash`, custom tools, hooks and process agents run, so their writes come back only through carry-back. | `crates/trellis-loop/src/isolate.rs` | 0032 |
| **ticket** | A GitHub issue labelled by the ticketing standard's dimensions (`area:`, `kind:`, `risk:`, `surface:`, `effort:`, `origin:`, flags). Ready when G0 passes. Triage is deterministic rules in `trellis-tickets`, never a model call. | `docs/TICKETING.md`; `crates/trellis-tickets/` | 0040 |
| **tier** | How a well-formed tool call is obtained from a model: 1 `Native` (the provider's tool-calling API, hosted), 2 `RuntimeConstrained` (schema in the runtime's guided-decoding field), 3 `HarnessConstrained` (not built, descoped), 4 `ValidateAndRetry` (no schema; parse and retry). `trellis doctor` and every run report the active tier. | `AdapterTier` in `crates/trellis-model/src/tier.rs` | 0006, 0013, 0024 |
| **ToolResult** | What a tool hands back to the model: `Radius`, `Checks(Verdict)`, `FileContent`, `Edit`, `Output`, `Error`. No pass variant (rule 2); only `Checks` can carry a passing claim. | `crates/trellis-loop/src/tools.rs` | 0004 |
| **ToolSet** | The tools a run offers, built once at run start from `[tools]` and handed to the prompt, the schema, the parser and the orchestrator. Default on: `blast_radius`, `read_file`, `edit`, `run_checks`, `read_skill`. | `ToolSet`, `BUILTIN_TOOLS` in `crates/trellis-loop/src/registry.rs` | 0023 §1 |
| **trail** | One JSON document per run at `.trellis/runs/<timestamp>-<slug>.json`, committed by itself, for failed runs too. Split into `factual` (what happened, with `factual_sha256` over it) and `judgment` (what a model said). | `Trail`, `Factual`, `Judgment` in `crates/trellis-trail/src/lib.rs`; `record_trail` in `crates/trellis-cli/src/run_cmd.rs` | 0007, 0034 |
| **trust / `trellis trust`** | Consent to run a repository's own code (hooks, custom tools, `bash` settings, process agents). Recorded outside the repository as a digest over everything that would run; any change makes the repository untrusted again. Trusted code must live under `.trellis/`. `trellis trust` prints what would run and records the consent; `--show` and `--revoke` inspect and remove it. | `TrustStore`, `TrustGuard` in `crates/trellis-loop/src/trust.rs`; `crates/trellis-cli/src/trust_cmd.rs` | 0023 §4 |
| **unresolved edge** | An edge whose target is `Target::Unresolved(Reason)`: statically invisible, with a reason such as `MethodDispatchUntyped`, `DecoratorIndirection`, `StarImport`, `DynamicAttribute`. Counted as doubt, never dropped, unpartitionable. | `Target`, `Reason` in `crates/trellis-index/src/graph.rs` | 0002, 0003 |
| **untrusted trail** | A trail as read back: it lives in a repository that takes contributions, so it is data. Checks come back as `RecordedCheck`; judgment text is fenced and labelled when fed to a model (rule 10). | `UntrustedTrail` in `crates/trellis-trail/src/untrusted.rs` | 0007, 0038 |
| **vault** | A directory of Markdown notes in the Apex format: frontmatter of exactly `title` and `parent`, an acyclic parent graph, a `manifest.json`. Configured with `[context] vault`. Model writes are refused at its notes root. Inspected and edited by people with `trellis vault`. | `crates/trellis-vault/` | 0017, 0022, 0049 |
| **Verdict** | Proof that a check executed and what it concluded. `passed` is true exactly when the process exited 0. Private fields, a private `Seal`, `pub(crate)` constructors each taking a `ProcessOutput`, `Serialize` but not `Deserialize` (rule 1). | `crates/trellis-checks/src/verdict.rs` | 0004 |
| **Verified vs Reviewed** | Two claims about a caller of changed code, never added together. Verified: an executed test covered the call site's own line and passed. Reviewed: no test covered it; a model read it and did not object, a weak signal. | `AuditMode` in `crates/trellis-checks/src/verdict.rs`; `crates/trellis-checks/src/coverage.rs` | 0003 |
| **work unit** | A named target for a multi-agent run (`trellis run --agents N --target <symbol>`), resolved as `trellis radius` resolves symbols. | `WorkUnit` in `crates/trellis-loop/src/partition.rs` | 0045 |

Terms checked and left out: none of the requested ones. "Heartbeat" in
the code is `trellis work`; there is no separate heartbeat process.
