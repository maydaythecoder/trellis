# v0.1 — Measure

**No product ships from v0.1. Its output is numbers.**

The purpose is to replace assumptions with measurements before anything is
built on them. Two of those measurements decide whether the rest of the
project is the project described in `00-index.md` or a smaller one.

Status: **substantially complete.** The index is built and the recall figure
exists. The model floor does not, because it needs inference, which is v0.2.

## 3. The index

Two passes plus a resolve step, in `trellis-index`, depending on no model.

**Pass 1** parses each file with tree-sitter and collects definitions,
imports, call sites, **name bindings**, and **type facts**. The last two are
not in the original design and both are load-bearing:

- *Bindings* (parameters, assignment targets, loop and `with` aliases) exist
  for soundness. Without them `def f(callback): callback()` binds to any
  module-level `callback`, which is an unsound edge.
- *Type facts* (annotations, constructor assignments, base classes) exist for
  reach, and are the subject of ADR 0012.

**Pass 2** maps dotted module paths to files, src-layout aware, and discards
anything resolving outside the repository root.

**Resolve** walks each call site's scope chain outward, then the import table,
following `__init__.py` re-exports to depth 4. Emits `Resolved`, `Candidates`,
or `Unresolved(Reason)` — never two collapsed into one.

### The one thing that is easy to get wrong

Sharing a root package does not make a module first-party. poetry imports
`poetry.core.*` **379 times** and `src/poetry/core/` does not exist —
poetry-core is a separate distribution. Judging first-partyness by the root
package alone put those 379 imports in the recall denominator as misses.
Fixing it moved `Name`-shaped binding from 71.7% to 86.2%.

## 4. Cost (inputs to S9)

Release build, warm page cache, three runs:

| | |
|---|---|
| Full index build | **116.9 / 118.9 / 119.2 ms** |
| Peak working set | **37.9 MB** |
| `.trellis/index.bin` (postcard) | **599.5 KiB**, ~7 bytes per line (recorded in 26d31a3; BENCHMARK_AND_EVAL.md §1's 589.7 KiB was recorded earlier, in 05a2b35) |
| `trellis radius` against a warm cache | **48 ms** total process time |

Roughly 690 lines/ms for parse *and* resolve, against ~1,400 lines/ms for
Pass 1 alone — resolution roughly doubles parsing, and neither is close to the
constraint at this size.

### Incremental update (built 2026-09-19)

`Session` holds a repository open across edits, keeping each file's parse tree
and extracted facts. An edit derives an `InputEdit` from the old and new text
(common prefix and suffix), applies `Tree::edit`, and reparses that one file —
tree-sitter touches only the affected byte ranges and no other file is
reparsed at all.

Measured on the benchmark corpus, 30 successive edits to a median-sized file:

| | |
|---|---|
| Cold build | 119.4 ms |
| Session open (parse + retain trees) | 129.0 ms |
| **Single-file save, p50** | **39.7 ms** |
| Single-file save, p95 | 42.4 ms |
| Speedup vs cold build | **3.1×** |

**Parsing is incremental; resolution is not.** The graph is rebuilt from
cached facts on every edit, and that is a deliberate stopping point rather
than unfinished work. Symbol ids are dense indices into one arena, so changing
a file's definition count shifts every later id; a partial re-resolve would
need either a stable id space with per-file slack or a renumber-and-patch pass
over every edge referring to a moved symbol. Both are real designs and both
put a correctness risk into the structure every claim in this product rests on.

The measured trade says not yet: resolution is ~88 ms of a ~120 ms build, so
the remaining win is bounded by that, and 39.7 ms is already inside the range
where an editor feels immediate. When resolution stops being cheap — S9 puts
that above ~300k lines — the stable-id design is the next thing to build.

A property test asserts the thing that makes the cache trustworthy: **an
updated session is indistinguishable from opening the edited repository
cold** — same coverage, same edge count, same symbol count, same fingerprint.

## 5. Recall, first measurement (resolves S1's reach; fired S16)

400 call sites drawn uniformly, seed 20260919, audited **blind** — the auditor
saw the call site and its source, never the resolver's verdict, against rules
written down in advance. 159 had a first-party true callee.

| | |
|---|---|
| **Recall** | **47.8%** (76/159) |
| 95% CI | **[40.0%, 55.6%]** |
| **Precision** | **100.0%** (76/76) |
| Wrongly excluded as external | **0** of 114 |

| stratum | n | recall |
|---|---|---|
| `Name` | 72 | 84.7% |
| `Attribute` | 87 | 17.2% |
| `src/` | 36 | 58.3% |
| `tests/` | 123 | 44.7% |

**The whole interval sits below the 60% pivot trigger that ADR 0002
pre-registered on 2026-09-18, before the resolver existed.** The
pre-registration did its job: the number arrived and the rule was already
written, leaving no room to argue about where the line should have been.
ADR 0011 records it.

### A correction to this document's own method

The originally stated ±3.5pp interval was wrong. It assumed the recall
denominator equals the sample size. It does not — first-party sites are ~38%
of call sites, so 400 draws put ~150 in the denominator and the interval is
~±8pp. **A future audit must size its sample on the expected first-party
count**: roughly 1,000 draws to put 400 in the denominator.

## 6. The `Reason` distribution, which falsified a prediction

The design predicted `DecoratorIndirection` would dominate the misses, on the
strength of 20–41% decorated-definition density across the candidate repos.
S1's recorded patch was built on that prediction.

Measured, over 11,233 unresolved sites:

| reason | count |
|---|---|
| `MethodDispatchUntyped` | **10,646** |
| `LocalBinding` | 558 |
| `DynamicAttribute` | 22 |
| `DecoratorIndirection` | **3** |
| `StarImport` | 2 |
| `UnboundName` | 2 |

A factor of roughly 3,500 in the opposite direction. The density was real and
simply did not predict the miss distribution: decorated definitions are rarely
*called by name* from first-party code. Writing the decorator-unwrapping pass
would have cost 3–5 days to address 0.03% of the misses.

What the misses actually were, from auditors' own reasoning: **51% cite pytest
fixtures**, and the recurring pattern is a receiver whose type is stated
locally — `self._x = SomeClass()` in `__init__`, or an annotated parameter.
poetry is mypy-strict.

## 7. Recall, second measurement (ADR 0012)

Given the option to pivot or to attempt one bounded backstop, the project
owner chose the backstop. ADR 0012 records the deviation from the
pre-registered rule and bounds it: the thresholds are unchanged, this is one
attempt, and the pivot is deferred rather than cancelled.

The backstop is annotation- and assignment-guided receiver typing: base
classes, parameter annotations, annotated assignments, and constructor
assignments including `self._x = Foo()`.

Re-scored against the **same** 400 sites — ground truth is a property of
poetry, not of the resolver, so no re-audit was needed:

| | before | after |
|---|---|---|
| Recall | 47.8% | **67.9%** |
| `Name` recall | 84.7% | 84.7% (unchanged — the backstop does not touch it) |
| `Attribute` recall | 17.2% | **54.0%** |
| Precision | 100% | **100%** |
| Ambiguous but covering the true callee | 2 | 15 |

### Unsound edges appeared, and were fixed rather than kept

The first pass scored 78.0% recall at **97.6% precision** — three unsound
edges, two causes. Precision is the constraint, not the score, so each fix was
taken even though each cost recall:

1. **A declared type is an upper bound, not an identity.** `installed:
   Repository` holding an `InstalledRepository` dispatches to the subclass
   override, so naming the base is a lie. Now `Candidates` over the base and
   every overriding subclass. Deliberately *not* applied to `self.m()`, where
   the audit protocol resolves to the enclosing class.
2. **`@contextmanager` was wrongly in the transparent-decorator allowlist.**
   The argument for it was that calling a decorated generator still reaches
   its body — true of the dependency, false of the call, since the decorator
   returns a factory. Same class of error as `property`, already excluded.

Fixing them cost ~7 points of recall. Under v1.0 gate item 2 that is the only
available trade.

### Confirmed on a fresh sample

Measuring on the sample the work was aimed at is measuring on the test set, so
ADR 0012 required a fresh draw before the figure counted: 300 sites, seed
20260920, 5 of 300 overlapping the first.

| sample | n | recall | precision | `Name` | `Attribute` |
|---|---|---|---|---|---|
| seed 20260919 | 159 | **67.9%** | **100%** | 84.7% (61/72) | 54.0% (47/87) |
| **seed 20260920 (fresh)** | 100 | **72.0%**, CI [63.2%, 80.8%] | **100%** | 87.0% (47/54) | 54.3% (25/46) |

Every figure in this table is final-state. The two samples agree on both
strata, which is a stronger consistency check than the pooled number alone.

**Candidate usefulness** — the exit-gate metric asking whether a `Candidates`
set is worth more than an `Unresolved`:

| sample | ambiguous sites | true callee present in the set |
|---|---|---|
| seed 20260919 | 20 | **20 (100%)** |
| seed 20260920 | 10 | **10 (100%)** |

Every candidate set the resolver emitted contained the true callee. That is
the result that justifies `Candidates` existing as a third outcome rather than
being collapsed into `Unresolved`: a user reading one is reading a short list
that demonstrably contains the answer. It is also a small sample of a rare
outcome, so it is a promising figure rather than a guarantee.

The two agree with overlapping intervals. Both are final-state figures, taken
after the third soundness fix described below. An intermediate reading of
71.1% on the first sample was recorded in git history before the fresh audit
caught the remaining unsound edge; it is superseded and should not be quoted.

**The fresh interval is entirely above the 60% pivot trigger and entirely
below the 85% gate.** The pivot is averted; the **S1 fallback band applies**,
so a further backstop is required before v1.0 can claim the blast radius.

### The fresh audit earned its cost immediately

It caught a third unsound edge that the original sample did not: `installed:
DummyRepository` bound at runtime to an `InstalledRepository` — a *sibling*
class, not a subclass, both descending from the class defining the method.
Searching subclasses of the declared type misses it; the override set that
matters hangs off the class the definition was **found** on.

That is the most instructive defect of the three, because it says plainly what
the backstop's inputs are worth: an annotation is evidence about the runtime
type, never proof. Python does not enforce it, and here it was simply wrong.

## 8. Soundness, checked over every edge

`examples/check_soundness.rs` verifies a necessary condition on **every**
`Resolved` edge: the symbol named must be the final identifier of the call
expression that produced it.

| corpus | edges | violations |
|---|---|---|
| poetry 2.5.0 | 6,094 | **0** |
| second corpus (371 files) | 3,112 | **0** |

This matters because the gate asks for zero unsound edges across the corpus,
and a 400-site audit bounds the *rate* — a rate low enough to go unobserved at
400 sites still leaves dozens across 15,000 edges. The check is necessary but
**not sufficient**: an edge to the wrong `foo` in a different module satisfies
it, and only the audit catches that. Neither substitutes for the other.

## 9. What v0.1 leaves open

- **The model floor (S7).** Seven metrics, check-recovery rate primary,
  reported as a configuration rather than a parameter count. Needs inference.
  Measured in v0.2: three configurations, all below the floor
  (BENCHMARK_AND_EVAL.md §5).
- **A human auditor.** Both audits here were model-read where the protocol
  asks for human-read. The protocol was followed exactly and spot-checks were
  verified by hand, but a model auditing a call graph is not the independent
  evidence the method asks for. A-34, Q-15. **Required before any v1.0 gate
  claim.**
- **S6, which got worse.** `trellis radius Factory` reports 92 resolved call
  sites alongside 2,382 unresolved ones in the files it touches. That is the
  honest report and it is also unusable as a screen. Degradation UX is now a
  v0.3 blocker, not the v1.x item originally scheduled. Q-16.
