# ADR 0036 — v0.1-resolver is protected by a local pre-push hook

**Status:** Accepted.
**Date:** 2026-09-29
**Decided:** 2026-09-28 by the owner, via the coordinator (issue #22)
**Builds on:** `docs/BUILD_SYSTEM.md` (the `drain` integration branch)

## Context

`v0.1-resolver` is the main branch. It is meant to move only when the owner
merges a pull request on GitHub: agent work collects on the integration branch
`drain`, and `drain` reaches `v0.1-resolver` through its PR
(`docs/BUILD_SYSTEM.md`). Nothing on GitHub enforces that. The repository is
private on a free personal plan, and on 2026-09-28 both branch protection and
repository rulesets for it returned HTTP 403; GitHub offers neither on a
private repository without Pro.

## Decision

The protection is a `pre-push` hook, tracked as `scripts/hooks/pre-push` and
installed into a clone's `.git/hooks/pre-push` by `scripts/hooks/install.sh`.
For every ref being pushed it compares the remote ref with
`refs/heads/v0.1-resolver` and, on a match, prints

```
pre-push: refusing to push to v0.1-resolver; merge through a pull request on GitHub
```

and exits 1, which makes git abort the whole push. The check is on the remote
ref only, so it refuses an update, a force-push and a deletion alike, to any
remote, whatever the local branch is called. `git push --no-verify` skips it;
that is the deliberate bypass, and using it is the owner's call.

Files under `.git/hooks/` are never tracked, so until #217 the hook lived only
in the owner's clone, with a copy of its body kept in this ADR. It is now
tracked as `scripts/hooks/pre-push`, and `scripts/hooks/install.sh` copies it
into the shared git dir beside the pre-commit hook, so a new clone gets it by
running that script. `scripts/checks/pre-push-selftest.sh` installs it in a
throwaway clone and shows it refuses a create, update, force-push and deletion
of `v0.1-resolver` on a throwaway bare remote, and lets a push to `drain`
through.

## The gap

The hook guards one clone, and only against itself. It is not protection in
the sense GitHub's would be:

- A push from **any other clone** (another machine, a clone that has not run
  `scripts/hooks/install.sh`, a CI job holding a write token) reaches
  `v0.1-resolver` unchecked, including a force-push or a deletion.
- The **GitHub web UI and API** are unguarded: a direct commit or file edit on
  `v0.1-resolver`, a merge of a PR whose checks failed or never ran, and
  deleting the branch all go through.
- `--no-verify`, or a `core.hooksPath` that points away from `.git/hooks`,
  disables it in this clone too.

What holds `v0.1-resolver` today is the hook plus the practice that only the
owner merges into it. Nothing stops a mistake made outside this clone.

## The ruleset to apply if the repository goes public or gets Pro

When branch protection or rulesets become available (the repository is made
public, or the account moves to Pro), apply a ruleset targeting
`v0.1-resolver` that:

1. **Requires a pull request** before merging.
2. **Requires status checks to pass**, naming the jobs in
   `.github/workflows/ci.yml`. A matrix job reports one check per leg, named
   `<job> (<os>)`. Issue #22 named five:

   | Check | Job in `ci.yml` |
   |---|---|
   | `test (ubuntu-latest)` | `test` |
   | `test (windows-latest)` | `test` |
   | `rollback-gate` | `rollback-gate` |
   | `index-invariants` | `index-invariants` |
   | `precision-gate` | `precision-gate` |

   `ci.yml` has since gained `local-only` (both OSes), `guards` and
   `supply-chain`. Require those as well: the rule is every job in `ci.yml`
   at the time the ruleset is applied, read from the file then, not from this
   list.
3. **Blocks force-pushes.**
4. **Blocks deletion.**

Once that ruleset is in place the hook is redundant but harmless, and can
stay.

## What changes our mind

- The repository goes public, or the account gets Pro: apply the ruleset
  above, and mark this ADR superseded by the ADR that records it.
- A push to `v0.1-resolver` that did not come through a PR is found in its
  history: the gap has been used, and the case for paying for Pro is made.

**Amended 2026-10-04 (#378):** ADR 0051 adds `main`, the launch branch, to
what the hook protects; `v0.1-resolver` stays protected as the frozen legacy
default.
