# v1.0 — The harness

The version you use daily. A hard gate: **all five conditions, no
substitutions.**

Status: **two conditions have evidence, three do not.** Nothing here is
claimable until v0.2 and v0.3 ship.

---

## The gate, verbatim

1. **Recall on the benchmark repository meets the v0.1 threshold.**
2. **Zero unsound edges** — every `Resolved` edge verified real on the
   benchmark corpus.
3. **A real change runs to human approval** with a complete committed trail
   and grounded checks.
4. **Induced mid-run failure returns the repository to its exact pre-run
   state.**
5. **Resumption works.**

Plus: acceptable operation on a local open-weight model at or above the
measured floor, via constrained tool calling.

---

## Where each condition stands

### 1. Recall — **not met, and the shortfall is known**

The threshold is **85%** (ADR 0002, set 2026-09-18 before the resolver
existed). Measured **72.0%**, CI [63.2%, 80.8%], on a fresh sample.

That is above the 60% pivot trigger and below the gate, which puts the project
in the **S1 fallback band**: the import-scoped resolver plus receiver typing
is insufficient alone, and a further backstop is required before v1.0.

The evidence about *which* backstop is unusually specific, and is the most
valuable thing v0.1 produced beyond the number itself:

All figures below are **final-state**, measured after the receiver-typing
backstop and all three soundness fixes:

| stratum | seed 20260919 | seed 20260920 |
|---|---|---|
| `Name` | 84.7% (61/72) | 87.0% (47/54) |
| `Attribute` | 54.0% (47/87) | 54.3% (25/46) |

- `Name`-shaped callees are **essentially at the gate already**.
- `Attribute`-shaped callees carry the entire deficit, and the two samples
  agree closely on how large it is.
- `DecoratorIndirection` is **3 sites out of 11,233**. The decorator-unwrapping
  pass the original S1 patch reaches for first would address 0.03% of misses.
- 51% of first-party misses cite **pytest fixtures**; the pattern is a receiver
  whose type is stated locally.

Receiver typing already took the obvious version of that. What remains is
narrower: `conftest.py` fixture return types, container element types, and
return-type propagation — each of which ADR 0012 deliberately left out of
scope. Pyright over LSP stays the recorded fallback, with the cost of a Node
process in the critical path of a tool whose selling point is running locally.

### 2. Zero unsound edges — **on track, with real evidence**

| check | result |
|---|---|
| Precision, audited sample seed 20260919 (n=159) | **100%** |
| Precision, audited sample seed 20260920 (n=100) | **100%** |
| Mechanical necessary-condition check, poetry | **5,908 / 5,908 clean** |
| Mechanical necessary-condition check, second corpus | **3,112 / 3,112 clean** |

The two methods are complementary and neither substitutes for the other. The
audit catches an edge that names the *wrong* `foo`; the mechanical check
catches an edge naming something the source never called, and it does so over
*every* edge rather than a sample — which matters because a 400-site audit
bounds the rate, and a rate low enough to go unobserved at 400 sites still
leaves dozens across 15,000 edges.

**Three unsound edges were found and fixed during v0.1**, each costing recall:
subclass override of a declared type, `@contextmanager` wrongly treated as
transparent, and a sibling class overriding a method under an annotation that
was simply wrong. The third says what the others imply — an annotation is
evidence about the runtime type, never proof.

### 3. A real change to human approval — **not met**

Needs the loop (v0.2) and the trail (v0.3).

### 4. Induced mid-run failure — **partially met**

Rollback is built and verified by an induced mid-run panic in the test suite.
**CI is not configured**, and the gate says "verified by induced mid-run
failure in CI". Standing up CI is a v1.0 task, not a v0.2 nicety.

### 5. Resumption — **not met**

Needs v0.3.

## Also required before the gate is claimed

**A human auditor.** Both v0.1 audits were model-read where the protocol asks
for human-read (A-34, Q-15). The protocol was followed exactly — blind sample,
verdicts withheld, rules written in advance — and spot-checks were verified by
hand against the poetry source. But a model auditing a call graph is not the
independent evidence the method asks for, and the gate is exactly the place
that distinction is worth money.

Sizing note: a future audit must set its sample size on the **expected
first-party count**, not the draw. First-party sites are ~33–40% of call
sites, so ~1,000 draws are needed to put 400 in the denominator.

**Auditor disagreement, quantified.** Across chunks, first-party rates ranged
17%–57%, and auditors split on pytest-fixture injection (22 first-party
against 16 not, on the fresh sample). Because `is_first_party` sets the
denominator, this moves recall in a way the confidence interval does not
capture. A single human auditor applying one rule removes this source
entirely, which is a second reason to do it.

**A protocol gap, now closed.** One auditor flagged that the rules were silent
on framework-injected callables — a pytest fixture returning a closure defined
under `tests/`, then called as `factory(...)`. Rather than guess, they recorded
the closure as first-party and said so explicitly in the `reasoning` field, so
the three affected sites could be re-bucketed without re-auditing. That is the
behaviour the protocol wants from an auditor who meets an unwritten case.

The rule is now written (`audit_sample.rs`, rule 5): such a call resolves to
the returned definition when the fixture is defined exactly once and its return
is a definition you can point at — the injection is dependency injection, the
same as a typed parameter. `dynamic` is reserved for a parametrised fixture,
one overridden in several conftests, or a return you cannot name. The
judgements already recorded match that rule, so no figure changes.

## v1.0 non-goals, explicit

Any language but Python. Repositories without a test suite. Cross-repo
analysis. Any surface beyond the CLI. Any networked component. Multi-user
anything. Running while the machine is asleep. Multi-agent execution — that is
v1.1 and is gated on single-agent numbers that do not exist yet.
