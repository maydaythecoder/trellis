### Findings below Critical

**F1 (High): in a partial clone, trellis's own git runs a program that
`.git/config` names. The Atlas now triggers this on open.**

- **Where:**
  - `crates/trellis-vcs/src/history.rs:412-419`: `cat-file --batch`,
    spawned through `command()`.
  - It is reached from `crates/trellis-cli/src/atlas.rs:49` (`tree_copy`).
  - The page asks for it on its own: `desktop/ui/atlas.js:418` sends
    `get_codebase {ref}` for every planned snapshot when the section is first
    shown (atlas.js:26-29 and `pump`).
- **Already on main:**
  - `crates/trellis-vcs/src/lib.rs:831`: `git --no-pager diff HEAD`, called
    by `session.rs:775` `show_pending` after a run.
  - The rollback's `reset --hard` in `reset_and_clean` (lib.rs:854-866).
- **Mechanism:**
  - If a blob is missing and `.git/config` declares a promisor remote, git
    fetches the blob lazily.
  - The fetch runs the transport that config names: `remote.<r>.uploadpack`
    for a local path, or `core.sshCommand` for ssh.
  - `command()`'s overrides (`core.fsmonitor=`, `core.hooksPath=/dev/null`)
    do not cover this.
  - A planted `protocol.<name>.allow=always` beats `-c protocol.allow=never`.
- **What it contradicts:**
  - ADR 0023 (lines 717-719) leaves `core.sshCommand` and credential helpers
    un-overridden because they "run commands only in commands trellis does not
    run". That premise is false.
  - ADR 0025 §5 (line 863) records the fetch, but not that the fetch executes
    a command named by config.
- **Precondition:** an attacker-supplied `.git/` (config plus object store).
  - Examples: a repository received as an archive or on a shared folder, or a
    run's escape by absolute path, which ADR 0032 lists as best-effort.
  - A plain `git clone` of a hostile remote does not give this, because clone
    writes its own config.
  - The env is the scrubbed one `command()` gives, so provider keys are not
    in the planted program's environment. It still runs as the user.
- **Reproduction (git 2.43.0, run in the scratchpad, the argv trellis
  builds):**
  ```sh
  git init -q evil && cd evil && echo 'X = 1' > a.py && git add a.py && git commit -qm one
  fake=$(printf 'Y = 2\n' | git hash-object --stdin)            # never written
  tree=$(printf '100644 blob %s\tb.py\n' "$fake" | git mktree --missing)
  git tag v2 "$(git commit-tree "$tree" -p HEAD -m two)"
  git config extensions.partialClone origin; git config remote.origin.promisor true
  git config remote.origin.url "$PWD"; git config remote.origin.uploadpack "touch ../MARKER; false"
  printf '%s\n' "$fake" | git -c core.fsmonitor= -c core.hooksPath=/dev/null cat-file --batch
  ls ../MARKER    # exists: the planted command ran
  ```
  - **Result:** `MARKER` was created.
  - The same holds with `remote.origin.url=ssh://example.invalid/x` and a
    planted `core.sshCommand`.
  - It also holds for main's `diff HEAD` and `reset --hard` once HEAD's blob
    is deleted from the object store.
  - `status`, `rev-parse`, `log -1`, a first-parent `log` and
    `for-each-ref --merged` did not fetch.
  - In the desktop, step 1 is opening the Atlas on such a repository with a tag
    from the last two years. Step 2 is the automatic `get_codebase {ref}`. The
    result is the planted program running as the user.
  - This was not run through a built trellis binary; see Unverified.
- **Fix (verified at git level):**
  - Set `GIT_NO_LAZY_FETCH=1` on `trellis_vcs::command()`,
    `command_with_hooks` and the env `git_argv`'s callers use.
  - With it set, `cat-file` answers `missing`, which `read_batch` already maps
    to `HistoryError::Missing`.
  - It held against a planted `protocol.ssh.allow=always`.
  - For a git too old to honour the variable, refuse a `ref` read when
    `extensions.partialClone` is set.
  - Add a trellis-vcs test that plants `uploadpack` and a missing blob and
    asserts no marker.
  - Amend ADR 0023's "not neutralised" list.

**F2 (Low): two properties ADR 0025 §5 states have no test that names them.**

- The copy directory is `0700` (`history.rs:559-563`).
- The copy is removed after a failure partway through the copy: the
  `Missing`, header and exit-status paths at `history.rs:447-455`.
- What is tested: removal on drop (`tree_copy_leaves_the_worktree_...`,
  history.rs:686) and an empty TMPDIR after a successful rpc
  (`rpc_atlas_get_codebase_ref_answers_..._writes_nothing`, cli.rs).
- Speculation: a regression in either would pass CI. No failure was
  reproduced.

**F3 (Info, speculation, not run on Windows): `safe_relative`
(`history.rs:528-536`) does not refuse two Windows name forms.**

- The forms:
  - A component with a trailing period: `.git./x.py` is written as `.git\x.py`.
  - DOS device names: `aux.py`, `nul.py`, `con.py`.
- Neither escapes the directory: Win32 resolves `.` and `..` before it trims
  the trailing period. The worst result is a `.git` folder of `.py` files in a
  copy where no git runs, or one snapshot refused or short a file.
- Recommendation: refuse what git's `core.protectNTFS` refuses.

**F4 (Info): a copy survives SIGKILL, abort or power loss.**

- Nothing sweeps stale `trellis-tree-*` directories. On Unix they are `0700`.
- Normal shutdown removes them: the rpc joins its waiters on stdin EOF
  (rpc.rs:780), and the desktop's `shutdown` closes stdin and waits.
- An unwinding panic also removes them; `panic = "abort"` is deliberately off
  in Cargo.toml.
- Blob size is unbounded (`history.rs:487-488`). So is the HEAD index's
  `read_sources`; that is not new.
