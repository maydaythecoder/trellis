**Finding: CI does not build with `--locked`.** Only these steps pass
`--locked`: `cargo deny` and `cargo install` in the `supply-chain` job, and
`fuzz-lock-current.sh`. These do not:

- `cargo test --workspace` and `cargo clippy` in `test`;
- `cargo build/test --no-default-features` in `local-only`;
- every `cargo test` / `cargo run --release` in `rollback-gate`, `guards`,
  `index-invariants` and `precision-gate`;
- `release.yml`'s test and build.

**Scenario.**

- **Input.** A change that edits a `Cargo.toml` requirement without the
  matching `Cargo.lock` update.
- **Step.** CI's `cargo test` resolves new versions and rewrites the lock in
  the runner's checkout.
- **Result.** CI passes on versions no reviewer saw. This defeats "Cargo.lock
  is the pin" in CLAUDE.md.

The `supply-chain` job's `cargo deny --locked` would fail on that same change,
so the gap is partly caught today. It is still caught by a different job than
the one that ran the tests, and `release.yml` has no such job. Reproduced
only in reasoning, not on a runner. See ticket T1.
