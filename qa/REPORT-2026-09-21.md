# QA Run — 2026-09-21

## Verdict

The chat TUI is usable now and was not when this run started: twelve defects
were found by driving it through a pty, nine of them things a user would hit in
the first ten minutes, and the worst was `/clear` telling the user their history
was gone while still sending every dropped turn to the model. The single biggest
remaining problem is now the **GPU**, not the code: two ollama daemons contend
for one 8 GB card, and when both hold weights the interface looks broken while
the configuration is what is wrong. Second to that, **`/stop`'s effect on a
conversation is only half understood**: it provably halts the stream and the child process, but whether
the *next* question gets answered on its own terms could not be established,
because the only real model available on the pty side is slow and sticks to the
previous topic.

## What I got working

- **TUI driven end-to-end through tmux in WSL**, at 80×24, 120×40 and 200×60,
  with streaming, scrolling, focus, resize, suspend/resume, panic recovery and

- **Ctrl-Z suspends and `fg` returns to a correct display.** Ctrl-Z used to type
  the letter `z`.
- **A graph pane on the side**, per `ui_examples/preview.webp` — nodes and

  `tool_calls` array, and the graph node goes `read_file ○─┐` to
  `read_file ●─┐ 1`. That bridge had only ever carried the mock's synthetic
  call, and the reason was that **the app offered the model no tools at all**.
- **Three models at 20/20/20/0** on the frozen fixture: `qwen3:8b`,
  `llama3.1:8b`, `qwen2.5:3b`.
- **A graph pane in the trellis TUI too**, where the call-graph data actually
  lives, plus `/graph` — which was typed in a real session and answered "not a

- **The TUI driven against a real model**, not only the mock — `llama3:latest`
  through WSL's own ollama. Session pane reports `llama3:latest / ollama (no

628 tests pass. `cargo clippy --all-targets -- -D warnings` is clean. No

| 2 | `gpt-oss:20b` | **Loaded, then took the host down.** Free RAM to 0.02 GB, pagefile 2.94 → 9.63 GB, 31 s to evaluate a 65-token prompt. Abandoned; recorded as unmeasured, not as zeros |

| 4 | llama.cpp + GBNF | **Not run, and now with a measured reason:** zero TEXT and zero PROSE-JSON across all 80 measured cases. The trigger is malformed output and none occurred |
| 5 | `llama3:latest` | Same refusal as rung 3. **Packaging, not the model** — see rung 3s |
| 6 | `qwen2.5:3b` | **20/20, 20/20, 20/20, 0/20.** TTFT 0.07 s with the GPU free, 19.2 s for 20 requests. 1.93 GB |

**Rung 4 is the one worth saying something about**, and it is still not run.
It exists to separate format failure from judgment failure, and it earns its
place only when the Ollama rungs fail on malformed output. Across **80 measured
cases on four models there was not one** TEXT or PROSE-JSON row. There is
nothing for a grammar to constrain.

A separate argument for llama.cpp did emerge, and it is not rung 4's: it is the
only route to measuring `gemma2` or `llama3` at all, because ollama's refusal is
missing template metadata rather than model inability. That is a coverage
question, not the malformed-output question rung 4 was specified to test.

**The binding constraint is a GPU, not system RAM.** This machine has an RTX
5060 Ti with 8 GB, and the two ollama daemons contend for it: with the Windows
one holding qwen3:8b, the WSL one was cut to 2.38 GB of VRAM and ran at a third
speed. That is very likely why llama3 took 20–70 s per reply during the §6 work
— which is what made those observations unreliable and produced two wrong
diagnoses. Operationally: pick one daemon for the TUI.

### Variations tried and what each did

| Change | Effect |
|---|---|
| `ollama run <model> "..."` (the §4.1 form) | **Hung.** The interactive REPL does not terminate on a single-shot prompt through a non-tty. Switched to the HTTP API, which returned `OK` in 6.5 s. Not a model problem. |
| `max_tokens` 8 | Empty completion, `finish_reason: length`. qwen3 emits reasoning first and it counts against the budget. |
| `max_tokens` 512, short prompt | Valid JSON returned. |
| `max_tokens` 512, 3,164-char prompt | **Empty**, `finish_reason: length`. |
| `max_tokens` 2048, same prompt | Correct tool call. This is what the fixture now uses. |
| `/no_think` appended | **Worse.** Via `/v1`: 12.47 s and 841 tokens against 5.34 s and 345 for the plain question — the model reasons *about* the directive. |
| `think: false` on `/v1` | **Silently dropped.** 415 completion tokens either way, byte-identical content, `reasoning` key present in both. Warm TTFT 5.61 s vs 5.56 s — inside noise. |
| `think: false` on `/api/chat` | **Works, 57×**: 6.31 s / 415 tokens / 1442 thinking chars → 0.11 s / 4 tokens / none. Wrong endpoint for this client; taking it means abandoning vendor neutrality, so it is reported and not taken. |
| `temperature: 0` | Used throughout; not varied. |
| Streaming on/off | Both exercised: streaming for TTFT, non-streaming for the 20 cases. |

Final config: `qwen3:8b` via ollama 0.34.2 at `http://127.0.0.1:11434/v1`,
`temperature: 0`, `max_tokens: 2048`, two tools, non-streamed.

**Two honest qualifications on that 100%.**

First, the argument check tolerates extra keys: cases 15 and 17 expect no
arguments and the model sent `{"filter": ""}`. That is counted correct, because
a model filling in an optional field it was offered is not the failure being
measured — but it is not literally what was asked for, so "20/20 arguments"
means "every expected key had the expected value", not "the object was
identical".

Second, this is one prompt shape per tool and the phrasing makes the choice
fairly obvious. It measures format reliability and selection on an easy task. It
does not measure selection under ambiguity, which is a different fixture and a
useful next one.

The machine was swapping (2.2 GB pagefile) with 2.9 GB free. Nothing failed
because of it, but the headroom on this box is thin and a 9 GB model would not
fit alongside what is running.

## Fixed

Full log with evidence in `qa/logs/10-findings.md`. Eleven (F12 is unresolved, see Blocked), in the
order found. *(Corrected 2026-10-05, #420: said "Twelve".)*

1. **`/clear` cleared the display and not the model's history.** Pane read
   `ctx 0 / turns 0`; the next turn reported 166 tokens where a fresh history
   costs ~21. A *confirmed* action that did not do what it asked permission for.
   `update` now emits `Effect::Run(Command::Clear)`; the runtime resets. Next
   turn is now 79 tokens. **Re-run: passes.**
2. **`/add` counted a file and threw it away.** `fs::metadata` only — it
   reported "~7276 tokens" having read no content. Now injects the text; added a
   2 MiB cap and a NUL check so a binary cannot be pushed into the window.
   ctx 0 → 2.5K. **Re-run: passes.**
3. **`/context` was a placeholder string.** Now lists each injected file with
   its estimate and a total. **Re-run: passes.**
4. **The conversation pane never followed the stream** — and the first fix was
   not enough. Two causes: no follow behaviour at all, and the scroll surface
   sized by *logical* lines while the `Paragraph` wraps. Eight turns is ~17
   logical lines, which fits a 28-row pane, so the offset stayed 0 while the
   content wrapped to ~50 rows and the rest was silently clipped. Now sized by
   wrapped height. Showed questions 1–6; now shows 4–8. **Re-run: passes.**
5. **The app wrote `chat.log` into the working directory**, dirtying the
   repository — which for TRELLIS blocks the next run (ADR 0009). Now
   `$XDG_STATE_HOME`/`$LOCALAPPDATA`, overridable with `CHAT_LOG`. **Re-run:
   passes** (no `chat.log` created in the repo). *(Note 2026-10-05, #420: the
   evidence log, `qa/logs/10-findings.md` F5, still records this as NOT YET
   FIXED and holds no re-run; treat this fix as open until it does.)*
6. **The footer advertised `q quit`** in an interface with a text input. Pressed
   it: a `q` appeared and the session stayed up. Footer corrected, with a test
   that fails if `q quit` returns.
7. **Ctrl-Z typed `z`, and every Ctrl chord typed its letter.** In raw mode the
   tty generates no SIGTSTP, so chords arrive as ordinary key events. `^W`, `^U`,
   `^A` all inserted text. Chords are now swallowed unless bound; `C-z` suspends
   properly. **Re-run: passes.**
8. **`/eng` generated a loop that was decorative.** `/test-loop` printed the cap
   and the state file and executed nothing. Verification commands are now parsed
   back out of the generated `.md` — the file is the source of truth, not a
   constant — and run through `LoopRunner`. **Re-run: cap and no-progress halts
   both observed.**
9. **`/stop` could not interrupt a loop**, for two separate reasons. The effect
   loop `.await`ed the running loop, so the `/stop` sat unread until it
   finished; and once delivered, the cycle body ran its child to completion
   while `/stop` describes itself as "kill running child processes". Loop is now
   spawned; `/stop` handled out of band and replaces the token (a cancelled
   token stays cancelled, which made the *next* loop halt instantly); `shell`
   polls and kills. **Re-run: passes.**
10. **`/delegate` was a stub** returning a formatted string. Now a real
    sub-agent with its own history. **Re-run: passes.**
11. **The first `Up` jumped to the start of the session.** The offset was
    absolute and still 0 while following, so one decrement saturated at the top.
    Now counted back from the newest line. **Re-run: passes.**

## Unverified

- **Most §6 results are against the mock.** The real-model pass covered
  streaming, the session pane, Ctrl-C and post-interrupt turns. It did **not**
  re-cover the commands, the loops, `/delegate`, resize, suspend or panic —
  those remain mock-only results.
- **The tool the model asks for is never actually run.** The call reaches the
  graph and the counter; nothing executes `read_file` and nothing feeds a result
  back. The loop is one-way, which makes the graph a record of intent rather
  than of work.
- **The four tool definitions were never validated against a second endpoint.**
  They are accepted by ollama; whether llama.cpp's server takes the same shapes
  is untested.
- **Only rung 4 was never run.** Rungs 2, 3 and 5 were attempted and could not
  be measured; 3s and 6 were measured (see *Model bring-up*). No rung failed on
  format, so there is no evidence about what happens when a model *does*.
  *(Corrected 2026-10-05, #420: this item said rungs 2–6 were never run.)*
- **Windows console behaviour is entirely untested.** `q`, `C-c`, `C-z`, resize
  and panic recovery were all checked on a Linux pty. Windows has no SIGTSTP and
  the suspend path is a deliberate no-op that reports "this platform has no job
  control" — a string no test has ever seen rendered.
- **`/approve`, `/agent`, `/steer` and `/compact`'s actual effect** are still
  stubs returning strings. `/compact`'s *confirmation* was tested; what it does
  after `y` was not, because it does nothing.
- **The `/add` glob and directory paths.** Only the single-file form was driven
  through the TUI. The directory and `*.ext` branches are covered by the new
  reader's structure but were never exercised against a real repository.
- **The graph pane at narrow widths in a live terminal.** Unit-tested down to
  zero width; rendered live only at 120×40 and in snapshots at three sizes.
- **Concurrent loops.** One loop at a time was run. Two `/qa-slow` invocations
  overlapping, and what `/stop` does to both, is untested — and the token is now
  shared across them, which I suspect stops both.
- **`wrapped_height` counts characters, not grapheme clusters.** It over-counts
  for combining marks, which is safe (a too-tall surface scrolls harmlessly) but
  means CJK and emoji-heavy transcripts will scroll slightly further than they
  need to. Never tested with either.
- **Whether the pagefile use was caused by the model.** 2,275 MB was in use with
  the model loaded; no baseline was taken before loading it, so the attribution
  is unproven.
